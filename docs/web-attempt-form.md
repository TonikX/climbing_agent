# Запись пролаза на сайте

Ручная проверка: [инструкция по тестированию](web-attempt-testing.md).

Кнопка «Записать пролаз» доступна после входа в личный журнал. Если тренировка
уже идёт, запись добавляется в неё. Иначе форма предлагает дату и тип места;
новая тренировка начинается вместе с сохранением первого пролаза.

Поля: район, сектор, трасса, категория, достижение конца, чистота, стиль,
страховка, число попыток. Срывы, зависания и комментарий необязательны.
Признак тестовой записи исключает её из статистики; режим тестирования
пользователя также применяется сервером. Верхняя — тип страховки, не стиль.

Поиск использует существующий `/catalog-search/{kind}` с многоязычными
названиями и транслитерацией. Сектора ищутся в выбранном районе. Пустой поиск
трасс показывает сектор, поиск по названию охватывает весь доступный каталог.
Выбор трассы подставляет её район, сектор и категорию. Новые названия
сохраняются в личном каталоге; при необходимости создаётся личная копия
общедоступного района и сектора, общий каталог не изменяется.

`POST /api/v1/web-attempts` принимает поля `WebAttemptCreate` и возвращает
`trainingId` и `attempt` (обычный AttemptResponse). Запрос использует cookie
сессии, проверку Origin/CSRF и `Idempotency-Key`. Создание личной иерархии,
тренировки и пролаза выполняется одной транзакцией. При ошибке всё откатывается.
Повтор того же запроса с прежним ключом не создаёт дубль. Завершённые и чужие
тренировки недоступны для добавления. Результат нормализуется общими правилами
бэкенда; LLM не вызывается. Миграция БД для этой формы не нужна.

Деморежим показывает заполнение и подтверждение, но ничего не отправляет в API.
После реального сохранения журнал и статистика перезагружаются; для просмотра
новой тренировки выбранный период должен включать её дату.
