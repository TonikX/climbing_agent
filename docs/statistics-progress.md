# Расширенная статистика

Все расчёты выполняются существующим FastAPI-сервисом из PostgreSQL. Входы
get_climbing_statistics и имена Telegram-команд сохранены, миграций БД нет.

Общая сводка считает трассы по route_session_key (при его отсутствии — id
попытки). is_test исключается до агрегации. Чистота берётся из clean_ascent,
достижение конца — из reached_top; эти правила не изменены.

- maxAttemptedGrade — максимум всех попыток; maxGrade сохранён как его alias.
- maxReachedTopGrade — максимум категорий в сессиях трасс с достижением конца.
- maxCompletedGrade — максимум категорий в сессиях трасс с чистым пролазом.
- completionRate — completedRoutes / routesCount; при отсутствии трасс — 0.
- attemptsPerRoute — attemptsCount / routesCount; без трасс — null.
- attemptsPerCompletedRoute — все попытки / чисто закрытые трассы; без чистых — null.

Последняя метрика включает попытки на незакрытых трассах и не является средним
числом попыток только на успешно закрытых трассах.

durationMinutes суммирует известную длительность уникальных тренировок с
нетестовыми данными в выборке. Неизвестные длительности пропускаются; если
известных нет, сумма равна 0. Пустые и полностью тестовые тренировки не входят.

month включает grades, полный previousPeriod и comparison. Текущий месяц
до сегодняшнего дня сравнивается с полным предыдущим календарным месяцем.
Явные dateFrom/dateTo сохраняются и для scope=week/month; пропущенные границы
определяются по указанной дате, а без дат — по текущему периоду. dateFrom после
dateTo даёт 422. Фильтры grade, routeId и route применяются одинаково к текущему
и предыдущему периоду; несколько фильтров объединяются условием «и».
grades сортируется по _grade_rank от высокой категории к низкой; «Без категории»
стоит в конце. progress содержит до шести последних месяцев с нетестовыми
данными, от нового к старому; Telegram показывает их в хронологическом порядке.

comparison вычисляется backend для тренировок, чистых трасс, доли закрытия,
попыток на чистый пролаз и максимальной чистой категории. Значения up/down/equal
описывают изменение числа (↑/↓/=); null означает, что сравнить нельзя.
Составные категории расположены между границами: 6B < 6B/6B+ < 6B+ < 6C.
Порядок частей в записи не влияет на сравнение.
Категории сравниваются через _grade_rank, не как строки. Снижение попыток на
чистый пролаз показывается ↓; это потенциально полезное изменение, а не
автоматическая оценка силы спортсмена.

Telegram отображает проценты, полоски из восьми символов, три максимума,
страховку и стили. Статистика по кнопкам по-прежнему обходится без LLM.

Проверки: npm test, npm run build, PYTHONPATH=backend pytest backend/tests.
Для полного backend-набора нужен PostgreSQL: тесты миграций создают временные
схемы в транзакциях и откатывают их. CI запускает отдельный PostgreSQL service.
