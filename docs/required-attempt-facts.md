# Обязательные факты пролаза

`reached_top` и `clean_ascent` сохраняются только как `true` / `false`.
Чистота не выводится из нулевых счётчиков или одного факта достижения конца.
Чистое прохождение подтверждает достижение конца; недостижение конца исключает
чистоту. Срыв, зависание и соответствующие комментарии исключают чистоту.
Onsight / Flash / Red Point подтверждают чистоту и конец только без противоречий.
Если модель не извлекла обязательный факт, бот уточняет его до сохранения.

`belay` обязательно: `lead`, `top_rope`, `auto_belay`, `bouldering`.
Неизвестная или отсутствующая страховка вызывает уточнение / HTTP 422.
`style`: `onsight`, `flash`, `redpoint`, `with_falls`, `with_hangs`, `unknown`.
`top_rope` исключён из стилей, схем AI, новых запросов, кнопок и подсказок.
Старые черновики с этим стилем преобразуются в верхнюю страховку; при конфликте
страховка запрашивается заново. Поле `result` остаётся для совместимости.

Правила действуют для REST, tools, AI, ручного ввода, массовых правок и summaries.
При частичной правке сохраняются уже известные факты; явный null не допускается.
Worker передаёт только заданные поля Intent, сохраняя различие между пропуском
и явным значением. Просмотр статистики не изменяет записи и не вызывает LLM.

## Исторические данные и развёртывание

Миграция `20261022_0020_required_attempt_facts.py` выполняется одной транзакцией:

1. При `style=top_rope` проверяет страховку. `unknown` становится `top_rope`,
   уже указанная верхняя сохраняется, другая известная страховка останавливает
   миграцию для проверки конфликта.
2. Стиль становится `with_falls` при положительных срывах, иначе `with_hangs`
   при положительных зависаниях, иначе `unknown`. Clean-стили не угадываются.
3. Восстанавливает только однозначные структурированные факты: нечисто при
   срывах/зависаниях/недостижении конца, конец при чистом пролазе или legacy send.
4. Если остаются неизвестные результат или страховка, останавливается с ошибкой.
   Все изменения откатываются. Срыв и project не доказывают недостижение конца.
5. После проверки включает NOT NULL для обоих фактов, ограничивает страховку
   известными значениями и исключает top_rope из CHECK стилей.

Перед обновлением кода остановить записи, сохранить backup, уточнить старые
неизвестные факты и применить миграцию штатной ролью миграции. Новая версия API
не должна запускаться со старой схемой и неполной историей. Для восстановления
исходных значений использовать backup: downgrade не отменяет исправленные факты.

Для отчёта только по проверенному владельцу запустить
`PYTHONPATH=backend python scripts/audit_attempt_facts.py --output output/attempt-facts-review.csv`
в окружении существующего API. Скрипт ничего не меняет в БД, использует
`ACCESS_APPROVER_TELEGRAM_ID` и пользовательский контекст RLS. Журналы других
пользователей в отчёт не входят. CSV содержит персональные записи и не коммитится.
Полную проверку всей БД выполняет миграция; чужие недостающие факты нельзя
заполнять по предположениям. Отчёт не является командой на изменение данных.
