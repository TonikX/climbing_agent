# Поиск района, сектора и трассы в PostgreSQL

Каталог БД — источник названий, ID и категорий. LLM извлекает факты из текста
или распознанного голоса, затем один общий поиск на бэкенде разрешает названия.
Каталог не передаётся целиком в LLM. Для кнопок, ручного поиска и форматирования
ответов вызовов LLM нет.

## Правила

1. Видны общий каталог и личные записи текущего пользователя. Чужие личные
   районы, их секторы, трассы и варианты названий не участвуют в поиске.
2. Нормализация убирает регистр, пробелы и пунктуацию, приводит турецкие и
   распространённые латинские диакритические символы к базовым буквам, ё к е.
   Это не автоматический перевод или транслитерация. «Гейкбаири» можно один раз
   найти по `Geyikbayırı`, выбрать запись и сохранить своё написание как алиас.
3. Одно точное совпадение имени/личного алиаса разрешается автоматически.
   Несколько точных совпадений и любые похожие совпадения требуют выбора.
   Сектор ищется только внутри выбранного района, трасса — внутри сектора.
4. Текущий район и сектор тренировки используются как контекст записи пролаза.
   Название и категория выбранной трассы берутся из БД. Если в сообщении указана
   другая категория, бот предлагает выбрать категорию из БД или пользовательскую
   для snapshot пролаза. Каталог при этом не меняется.
5. Если записи нет, бот предлагает уточнить поиск, открыть каталог или явно
   создать личную запись. До подтверждения каталожные сущности и пролаз не создаются.
   Отсутствующий сектор/трасса общего района сохраняется в личной копии иерархии;
   общий каталог не дописывается и не переименовывается пользователем.

Подтверждённый выбор по введённому написанию запоминает личный алиас. Это влияет
только на поиск этого пользователя, не добавляет глобальных синонимов. Алиасы
попадают в экспорт профиля и удаляются каскадно при удалении пользователя/цели.

## Telegram

- «Текущая тренировка → Выбрать трассу из БД»: район → сектор → трасса, страницы
  по 8 записей. На каждом шаге можно написать название для поиска без LLM.
- «Место тренировки»: выбор района и сектора тем же поиском.
- После выбора трассы «Уточнить вручную» позволяет заполнить результат,
  страховку и стиль кнопками без LLM. Текст/голос остаются альтернативой.
- Свободная запись и ручная форма проходят одинаковую проверку каталога перед
  сохранением. Существующие попытки и их исторические snapshots не мигрируются.
- Выбор привязан к текущей тренировке и черновику в `dialog_states`, живёт
  30 минут. Старые кнопки не выбирают произвольный ID; `/cancel` отменяет черновик.

## HTTP

Требуется обычная авторизация активного пользователя:

```http
GET /api/v1/catalog-search/locations?q=Geyikbayiri&limit=20&offset=0
GET /api/v1/catalog-search/sections?q=Kebap&parent_id=location_...
GET /api/v1/catalog-search/routes?q=Engesh&parent_id=section_...
POST /api/v1/catalog-aliases/locations/location_...
Content-Type: application/json

{"name":"Гейкбаири"}
```

Пустой `q` возвращает страницу каталога. `parent_id` ограничивает поиск детей;
для locations его передавать нельзя. `limit` 1–100, `offset` 0–10000.
Ответ поиска: `items` (id, name, grade, parent_id, location, country, visibility,
match=exact|similar, score) и `next_offset`. Рейтинг похожести — подсказка, а не
вероятность правильного распознавания. Запись алиаса идемпотентна по владельцу,
цели и нормализованному имени. В API явные POST создания остаются явным действием.

## Миграция и развёртывание

`20261015_0016_catalog_search.py` включает `pg_trgm`, создаёт функцию
`catalog_normalize`, B-tree индексы точного и GIN индексы похожего поиска,
таблицу `catalog_aliases` с FORCE RLS и правами runtime/control. Запускать
миграцию штатным `app.migrate_public` с ролью миграции перед обновлением API.
Импортёр не получает доступа к личным алиасам. Дополнительного сервиса поиска нет.

Поиск выполняет `SET LOCAL jit=off` в своей транзакции. В рабочем каталоге
оценка стоимости вложенных RLS-политик запускала компиляцию 826 JIT-функций:
около 14 секунд компиляции против 0,04 секунды выполнения без JIT. Настройка
не меняет глобальную конфигурацию PostgreSQL и сбрасывается при завершении транзакции.
