# Трассы и пролазы

На сайте показаны отдельно:

- **Трассы** (`routesCount`): группы попыток по `route_session_key`, включая
  недостигнутый конец. Если ключа нет, отдельная запись считается группой.
  Это не число уникальных объектов каталога за всю историю: одна трасса
  в разных тренировках считается отдельно.
- **Пролазы** (`ascentsCount`): отдельные сохранённые записи с `reached_top=true`,
  независимо от чистоты. Повторные прохождения увеличивают этот счётчик.

Поле `attempts` не умножает число пролазов: объединённая запись «3 попытки,
дошёл до конца» не доказывает три достижения конца. Для нескольких известных
прохождений нужны отдельные записи. Неизвестный результат не считается
достижением конца. Тестовые записи исключены из обоих показателей.

`reachedByBelay` сохраняет число групп трасс, достигнутых с каждым типом
страховки. Группы пересекаются: одну трассу можно пройти с разной страховкой.

Новый `ascentsByBelay` содержит непересекающиеся счётчики записанных пролазов
по lead / top_rope / auto_belay / bouldering / unknown. Сумма total равна
ascentsCount. Внутри каждой страховки clean + nonClean + unknownClean = total.
Веб-карточки показывают и пролазы, и достигнутые трассы; разбивка чистоты
относится к пролазам. Старые поля API не меняют смысл. Миграция БД не нужна.
