# Пролазы по страховке на веб-обзоре

В простом режиме — число трасс с достигнутым концом отдельно для нижней и верхней страховки.
В расширенном — дополнительно чисто / не чисто / неизвестно.

Одна единица — route_session_key (выход на трассу) в выбранном периоде для данного типа страховки.
Несколько попыток не увеличивают число трасс. Если в группе был чистый пролаз, он имеет приоритет.
Если чистого не было, но есть явно нечистый успешный пролаз — «не чисто»; иначе «неизвестно».
Попытки без достигнутого конца и тестовые записи исключены. Если один выход содержит оба типа
страховки с успешными попытками, он учитывается по одному разу в каждом типе.

Общее поле StatisticsSummary.reachedByBelay: lead / top_rope, каждое содержит
 total, clean, nonClean, unknownClean. Используется общий StatisticsService с фильтрами периода,
категории и места. Счётчики попыток не используются вместо счётчиков трасс.
Миграция не нужна. Для публикации требуются обновления API и веб-образа.
