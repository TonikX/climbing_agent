# API журнала — пользовательская авторизация (0.7.0)

Базовый URL: `https://<domain>/api/v1`. `/health`, `/ready` и `/docs` остаются
доступными без входа. Все endpoints данных требуют `Authorization: Bearer <token>`.
`X-User-ID`, user, userId и userName не дают права выбрать другого владельца.

## Вход через Telegram

Доверенный адаптер OpenClaw берёт ID из runtime-контекста отправителя, а не из
аргументов инструмента. Внутри Docker-сети он вызывает:

```http
POST /api/v1/internal/auth/telegram
X-API-Key: <INTERNAL_API_KEY>
Content-Type: application/json

{"telegram_id":"123456"}
```

Nginx блокирует весь `/api/v1/internal/` снаружи. Ответ содержит access_token,
token_type=bearer, expires_in=900. Заголовок Cache-Control: no-store.
Это служебное подтверждение личности, не публичный вход по произвольному ID.
Клиент Mini App пока не реализован: ему потребуется проверка подписанного initData.

При первом обращении создаются users + Telegram external_ref, имя «Скалолаз»,
часовой пояс Europe/Moscow. Совпадения имён не объединяют аккаунты. Существующий
Telegram external_ref сохраняет прежний user.id и все тренировки.

Случайный токен живёт 15 минут. В PostgreSQL хранится только SHA-256 токена.
Gateway кеширует сессии отдельно для каждого отправителя (до 256 записей в памяти).
При 401 он один раз получает новую сессию и повторяет запрос с прежним ключом
идемпотентности. Служебный ключ и токены не передаются модели и не выводятся в логи.
Статус users.status=blocked немедленно запрещает сессии и выдачу новых токенов.

## Профиль и личные данные

| Endpoint | Назначение |
| --- | --- |
| GET /me | Собственные id, имя, часовой пояс |
| PATCH /me | Изменить name и/или timezone (IANA); неизвестные поля и null запрещены |
| GET /me/export | Все собственные тренировки, включая тестовые, снаряжение и профиль |
| DELETE /me | Удалить профиль, тренировки, попытки, снаряжение, привязку Telegram и сессии |
| POST /auth/logout | Отозвать текущий токен |
| POST /auth/logout-all | Отозвать все текущие токены аккаунта |

Logout не блокирует Telegram-аккаунт: доверенный бот может снова войти.
После DELETE /me новое обращение к допущенному боту создаст новый пустой аккаунт.
Общий каталог локаций и трасс при удалении не затрагивается.
Удаление PostgreSQL-данных не удаляет автоматически историю Telegram, переписку
OpenClaw, копии у LLM-провайдера и резервные копии. Процедура оператора и границы
закрытого пилота описаны в [multiuser.md](multiuser.md).

Telegram-команды `/profile`, `/profile_name Антон`, `/timezone Europe/Moscow`
работают без LLM. Первый вход происходит при открытии `/journal` или `/profile`.

## Тренировки и инструменты

```http
POST /api/v1/trainings
Authorization: Bearer <token>
Idempotency-Key: <new-request-id>
Content-Type: application/json

{"date":"2026-10-05","environment":"outdoor"}
```

- GET /trainings — собственная история; include_test=true включает тестовые попытки.
- POST /trainings/{id}/attempts — добавить попытку в свою активную тренировку.
- POST /trainings/{id}/finish — завершить свою тренировку.
- POST /tools/{operation} — инструменты журнала, body: {"payload":{...}}.

Пример попытки: {"name":"Трасса","grade":"6A","reached_top":true,
"clean_ascent":true,"style":"flash","belay":"lead"}. Бот использует camelCase
контракт tools. Оба входа используют общую функцию записи попытки.
Чужой resource ID возвращает 404 для тренировок/попыток; чужое снаряжение
отклоняется. Каталог локаций, секторов и трасс общий для участников пилота.

## Повторные запросы

Для изменяющих инструментов и REST start/append/finish передавайте
Idempotency-Key (1–200 символов). Один ключ + то же тело возвращает сохранённый
ответ; другое тело даёт 409. Ключ ограничен пользователем и операцией, для REST
append/finish также тренировкой. Новый физический пролаз — новый ключ.
Без заголовка дедупликации нет. Запись и ответ фиксируются одной транзакцией.

REST и бот учитывают тестовый режим. Ключи трасс не пересекают тренировки;
тестовые и реальные попытки имеют разные ключи. Если mergeIntoActive совпадает
с несколькими попытками, весь запрос откатывается с 409: исправлять нужно
отдельные попытки по attemptId.
