# Сопоставление личного каталога с импортированным

`scripts/catalog_reconcile.py` запускается в окружении backend с настроенной
служебной БД. Область ограничена активным владельцем из
`ACCESS_APPROVER_TELEGRAM_ID`; другие пользователи не объединяются.

Режим по умолчанию только выводит план. Его нужно сохранить в защищённый файл
вне Git. `--plan /path/plan.json` репетирует изменения и откатывает транзакцию;
`--plan /path/plan.json --apply` фиксирует их. Перед применением обязателен
проверенный `pg_dump -Fc`. Сохраняйте план, исходный скрипт и результат рядом
с резервной копией.

План сопоставляет район с уникальным импортированным районом, затем трассу
по имени и категории внутри этого района. Допустимы перечисленные в коде
проверенные исправления написания. Категории существующих попыток участвуют
в проверке: конфликт, неоднозначность и неуказанные P1/P2 оставляются оператору.
Похожесть текста сама по себе не разрешает слияние.

Применение повторно строит план и сверяет его целиком. Устаревший или изменённый
план отклоняется. Блокируется пользователь и параллельный импорт; при ожидающих
мутациях или незавершённом вводе скрипт прекращает работу. Права БД не меняются.

Меняются ссылки `route_id`, район/сектор/название в snapshot, основное место
тренировки и связи с секторами. Исходная категория snapshot, попытки, их группы,
результаты, тестовые флаги, даты и длительность сохраняются и проверяются
контрольной суммой. Изменённым тренировкам увеличивается версия. Старые названия
сохраняются как личные алиасы. Общие каталожные записи не редактируются.

Удаляются только сопоставленные личные каталожные строки без оставшихся ссылок
из попыток, snapshots, тренировок, алиасов и внешних источников. Несопоставленные
трассы и необходимые для них личные районы/сектора сохраняются.
