# Закрытый Telegram-пилот — 0.7.0

## Реализованный объём

Один аккаунт users на Telegram identity, регистрация при первом разрешённом
обращении, собственное имя и timezone, отзываемые пользовательские сессии,
изоляция всех операций журнала. Вход для браузера/мобильного приложения,
пароли, email, публичная регистрация, социальные функции и платежи не входят.

Telegram ID берётся из доверенного контекста команды/инструмента. LLM не получает
служебный ключ, токен или возможность выбрать userId. Backend принудительно
подставляет пользователя из сессии даже при подмене JSON. История без владельца
больше не возвращает записи всех пользователей. Имена не являются идентификаторами.

users.status: active / blocked. Новых ролей администратора в публичном API нет;
управление допуском остаётся у оператора сервера. Одной БД достаточно: попытки
принадлежат тренировке, тренировка и снаряжение — user_id. Каталог трасс общий.

## Изоляция OpenClaw

Профиль deploy/openclaw/multiuser-pilot.json устанавливает per-channel-peer,
только инструменты журнала поверх minimal, запрещает доступ к файлам, shell,
другим сессиям, памяти, произвольным сообщениям и служебным инструментам.
Поиск памяти и memory plugin выключены, группы Telegram выключены, allowlist
сохраняется. Административные chat-команды config/bash/debug/restart выключены.

Нужен отдельный workspace из deploy/openclaw/pilot-workspace. Старые USER.md,
MEMORY.md, дневники и личные инструкции нельзя переносить в него. Ключи и
внутренние файлы Gateway доступны оператору; этот пилот не является публичной
платформой для взаимно недоверенных клиентов. Отдельная защищённая Telegram/LLM
интеграция нужна перед таким запуском.

## Развёртывание

1. Сохранить pg_dump, .env, OpenClaw config и старый workspace с ограниченными правами.
2. Создать новый каталог, например /srv/climbing-journal/openclaw/workspace-pilot,
   скопировать туда только файлы из deploy/openclaw/pilot-workspace и текущий
   skills/climbing-journal/SKILL.md в skills/climbing-journal/SKILL.md. Владелец — UID 1000.
3. В .env заменить OPENCLAW_WORKSPACE_HOST_DIR на новый каталог. Старый каталог
   оставить для отката. В контейнере путь остаётся /home/node/.openclaw/workspace.
4. Собрать API и Gateway. Перед переключением остановить Gateway, обновить API
   (он применит 0011), проверить /ready. Старый плагин несовместим с новой авторизацией.
5. Через одноразовый CLI-контейнер нового образа применить конфигурацию:

```sh
docker compose run --rm --no-deps --entrypoint node openclaw-gateway \
  dist/index.js config patch --file /opt/climbing-journal/deploy/openclaw/multiuser-pilot.json
docker compose run --rm --no-deps --entrypoint node openclaw-gateway \
  dist/index.js config validate
docker compose up -d --no-deps openclaw-gateway
docker compose exec -T nginx nginx -t
docker compose exec -T nginx nginx -s reload
```

Перед применением проверить отсутствие других agents.entries/list с отдельными
workspace/tool overrides и tools.allow: они могут конфликтовать с общим профилем.
На проверенном сервере таких overrides нет. Patch поддерживает --dry-run.
Не запускать параллельно второй Gateway с тем же Telegram-токеном.

Проверить loaded плагина, /health и /ready, Telegram /journal и /profile.
Без Bearer данные должны возвращать 401; /api/v1/internal/auth/telegram через
nginx должен возвращать 404. Первый вход существующего владельца сохраняет его
user.id. Для отката восстановить .env/config и предыдущие образы; удалять колонку
status или auth_sessions не требуется для старого кода.

## Допуск участников

До приглашения второго человека применить профиль и новый workspace. Добавлять
только известные положительные Telegram user IDs в channels.telegram.allowFrom;
не использовать username, имя или wildcard. Список ownerAllowFrom должен
содержать только оператора, а не всех участников. Не заменять allowlist на open.
Первое разрешённое обращение создаст аккаунт автоматически. Имя и timezone
пользователь задаёт через /profile_name и /timezone.

Для блокировки: удалить ID из allowFrom и установить users.status='blocked'
для соответствующего user_id в PostgreSQL; для немедленного отзыва старых сессий
удалить его auth_sessions. Секреты или Bearer-токены участникам в чат не отправлять.

## Личные данные и хранение

Минимальный профиль: имя, timezone, Telegram external_ref, статус, дата создания.
Телефон, дата рождения и медицинские данные не запрашиваются. Попытки, заметки,
снаряжение и test mode приватны. Названия трасс и локаций — общий каталог:
персональные заметки следует хранить в попытке/тренировке, а не в каталоге.

Экспорт /me/export включает собственный профиль, все тренировки и снаряжение,
включая тестовые записи. DELETE /me удаляет эти данные из PostgreSQL и сессии;
повторный вход допущенного Telegram-пользователя создаёт новый аккаунт.

Переписка OpenClaw, аудио/транскрипты, Telegram и резервные копии имеют отдельный
жизненный цикл. До подключения участников оператор должен определить сроки
хранения и уведомить, что сообщения/аудио обрабатываются внешним провайдером.
Запрос полного удаления включает адресное удаление пользовательской истории
OpenClaw и медиа и истечение резервных копий; SQL endpoint этого не обещает.
Восстановление backup должно учитывать ранее выполненные запросы удаления.
Экспорт и удаление через Telegram UI пока не добавлены, доступны API и оператору.

Логи приложения содержат имя операции, объём результата и задержку, но не
тело запроса, токен и личные заметки. Администратор БД технически имеет доступ
к записям; это разграничение доступа приложения, не шифрование от оператора.

## Проверки

Тесты PostgreSQL используют отдельные схемы и rollback. Проверяются совпадающие
имена разных людей, повторный вход, сохранение Telegram-привязки после миграции,
просроченные/отозванные токены, блокировка, подмена userId, чужие попытки,
тренировки и снаряжение, изоляция статистики/idempotency, экспорт и удаление.
Тесты плагина проверяют runtime identity, разные кеши токенов и сохранение ключа
при обновлении сессии. Авторизация и профиль по кнопкам не вызывают LLM.
