# OpenClimbing / OpenStreetMap: импорт каталога

Источник: https://openclimbing.org/export. Форма Download database публикует
POST `https://openclimbing.org/api/climbing-tiles/export`, возвращающий SQLite.
Выгрузку можно скачать браузером. Обход защиты и парсинг карт не нужны.

SQLite — только входной файл, не хранилище приложения. Скрипт использует
стандартную библиотеку Python 3.11+, открывает файл read-only и читает
**только climbing_features**. Таблицы пользователей, списков и чужих пролазов
не читаются и в PostgreSQL не переносятся. Полный исходный файл содержит и такие
таблицы: не добавлять его в Git и не публиковать. После обработки его можно удалить.

## Запуск

```powershell
python scripts/openclimbing_import.py path/to/export.sqlite `
  --bind location:relation/18501782=location_c79a7c4e-e852-4a9b-9fca-27149bb11508 `
  --bind section:relation/18501891=section_1bd0485204503a386a96e308e83e1036
```

Привязки проверены для текущего публичного Гейкбаири и существующего Gizlibahçe,
загруженного из PDF. На другом сервере проверить ID перед использованием.
Поиск по совпадающим названиям между источниками не выполняется автоматически.

Результат в `output/catalog/openclimbing/` (не включается в Git):

- `report.txt`: SHA-256 исходника, версия схемы, покрытие и ограничения;
- `catalog.csv`: нормализованные записи и исходные категории;
- `skipped.csv`: записи без достоверного имени или родителя;
- `aliases.csv`: подтверждённые точечные представления скальных объектов;
- `import.sql`: транзакционный план для PostgreSQL, **не выполняется скриптом**.

## Модель и проверки

Фильтр страны берётся из `countryCode=ru/tr` источника, не из языка названия.
Обрабатываются outdoor area/crag/route. Gym, ferrata и route_top исключены.
Корневая area/crag становится Location. Дочерние crag — Section, route — Route.
Для самостоятельного crag с маршрутами создаётся Section с его исходным именем.
Вложенные сектора получают составное имя; настоящая иерархия остаётся в исходных
OSM-связях и файлах проверки. Самостоятельные маршруты без известного родителя
не получают выдуманную локацию.

Важно: `parentId` — **OSM ID отношения**, а не внутренний `id` строки SQLite.
Идентичность хранится в external_refs: system=`openstreetmap`,
external_id=`node/123`, `way/123` или `relation/123`; URL ведёт к реальному OSM-объекту.
Ключи типов различаются. Циклы, межстрановые связи и неопределённые родители
не превращаются в ложную иерархию. Дубли одинаково названных секторов требуют
разрешения конфликта; скрипт останавливается.

Точка-указатель внутри отношения скального объекта объединяется с отношением
только при явном OSM membership, одинаковом имени и совпадении координат
с допуском 0.0002 градуса. Это проверка карты-указателя, не общий поиск дублей по имени.

В Route.grade попадает только явный `climbing:grade:french`. UIAA и другие
системы сохраняются в CSV как исходные данные; автоматической конвертации нет.
Выгрузка не гарантирует полный каталог страны или всех трасс района.

План SQL использует фиксированный advisory lock, публичные проверки для
существующих привязок, стабильные ID и контроль external_refs. Повторный запуск
того же плана не создаёт дубликаты. Это **первичное пополнение**, а не синхронизация:
существующие записи не перезаписываются, отсутствующие не удаляются.
Личные тренировки, попытки и снимки не изменяются.

Перед выполнением SQL нужны проверка `catalog.csv`/привязок и резервная копия.
Исполнять оператором миграций: роль AllClimb `climbing_importer_login` не имеет
права записывать внешний источник `openstreetmap`; её права не расширяются.
Прямой онлайн-импорт и еженедельное расписание пока не подключены.
