# Стиль «Не долез» и зависимости результата

Код стиля: `not_reached`. Он доступен в API, распознавании LLM, ручном вводе,
редакторе Telegram, форме сайта, карточках и статистике по стилям.

| Известно | Что заполняется автоматически |
| --- | --- |
| Стиль «Не долез» | Дошёл до конца = нет; чисто = нет |
| Дошёл до конца = нет | Стиль = «Не долез»; чисто = нет |
| Чисто = да | Дошёл до конца = да |
| Onsight / Flash / Red Point без противоречий | Чисто = да; дошёл до конца = да |
| Срыв, зависание или соответствующий стиль | Чисто = нет; достижение конца не угадывается |
| Чисто = нет | Достижение конца и конкретный стиль не угадываются |
| Дошёл до конца = да | Чистота и стиль не угадываются |

Неизвестные поля заполняются только по этим следствиям. Поэтому, например,
бот не спрашивает чистоту и достижение конца после ответа «Не долез».
Срывы и зависания при этом остаются отдельными счётчиками, даже если итоговый
стиль — «Не долез». Страховка от результата не зависит.

Частичная правка учитывает ранее сохранённые данные. Изменение стиля на
«Не долез» устанавливает оба результата в false. Явное исправление достижения
конца на true убирает прежний стиль «Не долез»; при наличии срывов или зависаний
выбирается соответствующий нечистый стиль, иначе unknown.
Одновременные явно противоречащие значения (`not_reached` и `reached_top=true`
либо `clean_ascent=true`) отклоняются API с HTTP 422.

Миграция `20261026_0021_not_reached_style.py` после `20261022_0020` разрешает
новый стиль, переводит исторические записи с явным `reached_top=false` в
`not_reached` и закрепляет двустороннюю связь CHECK-ограничением PostgreSQL.
Другие исторические результаты не угадываются. Счётчики и комментарии не
меняются. На рабочем сервере сначала необходимо решить оставшиеся неполные
исторические записи, блокирующие предыдущую миграцию 0020.

## Совместимый серверный релиз

В ветке `codex/not-reached-release` миграция 0021 применяется прямо после
0019. Отложенная строгая миграция 0020 исключена из этого релиза: исторические
NULL и legacy top_rope сохраняются. Двусторонняя связь not_reached включается
без требования заполнять неизвестные исторические результаты. Новый код
по-прежнему требует известные факты для новых записей.
